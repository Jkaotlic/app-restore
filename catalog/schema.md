# Каталог удалённых приложений

`ru-removed.json` — массив записей. Файл вшит в программу и раз в запуск подтягивается с
`https://raw.githubusercontent.com/Jkaotlic/app-restore/main/catalog/ru-removed.json`.
Свежая копия принимается, только если она проходит проверку ниже и в ней не меньше 80 % записей
от вшитой; иначе используется кэш, затем вшитая копия.

| поле | тип | обязательно | правило |
|---|---|---|---|
| `track_id` | число | да | больше 0, уникально |
| `name` | строка | да | не пустое |
| `aliases` | массив строк | нет | другие названия для поиска |
| `letter` | строка | да | 1–3 символа, буква на плитке |
| `color` | строка | да | `#RRGGBB` |
| `source` | строка | да | откуда взят id (ссылка или описание) |
| `status` | строка | нет | `removed` (по умолчанию) или `back_in_store` |
| `seller` | строка | нет | продавец; по нему скрипт ищет «новое имя или id» |
| `ipad_only` | логическое | нет | `true` — только для iPad (UIDeviceFamily = [2]); на iPhone строку не выбрать |

Неизвестные поля допускаются. Сведения о том, какие приложения есть у конкретного человека,
в каталог не попадают.

## Еженедельная проверка

`scripts/catalog-check.py` (Python 3, только stdlib) по понедельникам запускается из
`.github/workflows/catalog-check.yml`. `--dry-run` (по умолчанию) печатает отчёт, `--write`
правит файл. Отчёт: «Вернулись в магазин» (`status: back_in_store`); «Кандидаты: новое имя или id» (тот же
продавец, другой `trackId`; продавец сверяется с `sellerName` и `artistName`); «Неподтверждённые
кандидаты (совпало имя)» (продавец неизвестен или другой, но название совпало); счётчик «Нет в RU и US»
(для удалённых приложений это норма, поимённо выводятся только те, что раньше были `back_in_store`).
Приложения, найденные только поиском по разработчику (название не совпало), дают лишь строку «Другие приложения разработчика: N» и ни PR, ни issue не открывают. Уже имеющиеся в каталоге id в кандидаты не попадают. Если файл изменился, workflow открывает PR
(сам он не вливается); если файл не менялся, создаёт или обновляет issue
«Каталог: кандидаты недели».

## Ложные кандидаты

Если кандидат в отчёте ложный (другое приложение того же продавца), добавьте его id в
`ignored-candidates.json`: `[{"track_id": 123, "reason": "почему это не то"}]`. Такие id скрипт
исключает из всех разделов кандидатов, и они не вызывают issue. Файл лежит рядом с `ru-removed.json`
и в программу не вшивается.
